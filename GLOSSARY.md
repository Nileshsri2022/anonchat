# AnonChat

Anonymous, end-to-end encrypted messaging application over the Tor network.

## Language

**Contact**:
A remote peer whose cryptographic identity bundle and pre-keys have been imported and verified out-of-band.
_Avoid_: Friend, peer, buddy, user

**Direct Message (DM)**:
A pairwise, end-to-end encrypted conversation session between two Contacts using the Double Ratchet protocol.
_Avoid_: Private message, PM, 1:1 room, secret chat

**Message Envelope**:
The serialised transport structure containing a Double Ratchet header (ephemeral DH public key, sequence numbers) and encrypted payload.
_Avoid_: Message packet, payload, wire message

**Pairwise Channel**:
A deterministic relay identifier derived from hashing two sorted Contact public keys, enabling anonymous rendezvous without metadata leakage.
_Avoid_: DM room, private room, conversation ID

**Ratchet State**:
The client-side cryptographic state of an active Double Ratchet session (root key, chain keys, and DH keypairs) persisted in IndexedDB.
_Avoid_: Session token, session data, chat state

**Identity Bundle**:
The set of public key material (identity public key, signed Pre-Key, Pre-Key id) a Contact publishes so an Initiator can open a DM session to them.
_Avoid_: Pre-key bundle, key package, public profile

**Initiator**:
The DM peer who starts a session from a Contact's Identity Bundle and sends the first Message Envelope.
_Avoid_: Sender, Alice, opener

**Invite**:
The out-of-band artifact (QR or copyable string) carrying everything needed to join a Room or add a Contact, including key material that must never pass through the Relay.
_Avoid_: Link, share code, join code

**Profile Passphrase**:
An optional user-chosen secret stretched via PBKDF2 to seal all local persistence; unrecoverable if forgotten.
_Avoid_: Storage password, local password, device password

**Relay**:
The zero-knowledge message-passing server that stores and forwards opaque envelopes and never holds or derives key material for any conversation.
_Avoid_: Server, backend, chat server

**Responder**:
The DM peer who completes the X3DH handshake on receiving the first Message Envelope, using their own Pre-Key.
_Avoid_: Receiver, Bob, answerer

**Room**:
A multi-user conversation space secured by a Room Key (creator-generated and shared via Invite) or by a key derived from the Room Passphrase.
_Avoid_: Channel, group chat, chatroom

**Room Key**:
The symmetric AES-256 key protecting a Room's messages, generated by the Room creator and distributed only via Invite.
_Avoid_: Room secret, shared secret, room password

**Room Canary**:
An encrypted validation token stored with room metadata, used client-side to verify a Room Passphrase without revealing it to the relay server.
_Avoid_: Password hash, auth token, room signature, verifier

**Room Passphrase**:
A secret supplied by users and stretched via PBKDF2 with the room identifier to derive a Room's symmetric AES-256-GCM encryption key.
_Avoid_: Room password, channel secret, room PIN

**Safety Number**:
The verifiable cryptographic fingerprint derived from both peers' identity public keys, compared out-of-band to detect man-in-the-middle attacks.
_Avoid_: Verification code, security code, identity hash

**Skipped-Key Cache**:
A bounded in-memory table of derived message keys stored temporarily to decrypt delayed or out-of-order messages in a Double Ratchet session.
_Avoid_: Key cache, backlog buffer, replay cache

**PQ Handshake (Hybrid)**:
The DM session setup that combines classical ECDH with an ML-KEM-768 encapsulation so the root key resists future quantum attackers; both secrets feed one HKDF derivation.
_Avoid_: Quantum encryption, PQ replacement, Kyber swap

**PQ KEM Key**:
The ML-KEM-768 public key a client publishes in its Identity Bundle (signed like the Pre-Key) so Initiators can perform the PQ share of the hybrid handshake.
_Avoid_: Kyber key, quantum key, post-quantum certificate

**Sealed Sender**:
The envelope property that no sender identity appears on the wire; the recipient derives who sent a message inside the authenticated ratchet, and the Relay sees only an opaque destination.
_Avoid_: Anonymous sender, hidden header, senderless message

**Envelope v3**:
The wire format with sender identity stripped from the transport frame: channel id, ratchet header, ciphertext — nothing else.
_Avoid_: v2 envelope, extended header, rich envelope

**Sender Key**:
A per-member, per-Room symmetric key from which a member derives their own forward-secure message chain; distributed pairwise over DM ratchets, never via the Room Key.
_Avoid_: Group key, room sender secret, member key

**Sender Chain**:
The per-sender ratchet inside a Room: chain keys advance per message with a bounded skipped-key cache, so members authenticate who sent what and compromise of one member exposes only their own future until rotation.
_Avoid_: Group ratchet, broadcast chain, room session

**Intro Message**:
The single Room-Key-encrypted announcement (Identity Bundle + Display Name) a joining member posts so others can open pairwise DM channels to them; the only content the Room Key ever protects.
_Avoid_: Join message, hello packet, membership broadcast

**Unverified Badge**:
The UI marker on a member whose Identity Bundle has not yet been SAS-verified through the pairwise verification flow.
_Avoid_: Trust indicator, safety dot, verified tick inverse

**Blob**:
An opaque, encrypted file stored temporarily on the Relay under a size cap and TTL; its AES key travels inside the encrypted message, so the Relay stores ciphertext it can neither read nor attribute.
_Avoid_: Attachment file, media store, upload

**Outbox**:
The client-side encrypted queue of messages composed while offline, sealed under the Profile Passphrase scheme and flushed automatically on reconnect.
_Avoid_: Draft folder, send queue, pending tray

**Display Name**:
An optional, self-chosen label a client publishes in its Identity Bundle and Intro Messages; never required, never looked up, anonymity stays the default.
_Avoid_: Username, profile name, handle

**Design Tokens**:
The single fresh variables file (palette, light+dark, spacing scale) every surface styles through after the rebuild; there is no second stylesheet.
_Avoid_: theme file, CSS vars dump, globals copy

**Live Surface**:
The screens a user actually reaches (rooms/chat, DM, contacts, modals, settings); only these get primitives and styling effort.
_Avoid_: page inventory, all screens, UI scope

**Provably-Dead**:
A file, dependency, or export with zero inbound references proven by the automated import-graph detector; only provably-dead code is deleted.
_Avoid_: probably unused, looks dead, legacy
